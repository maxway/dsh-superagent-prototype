# 005 面板

[English](../005-panel.md) | **简体中文**

在 DeepSeek Harness Web 的侧边栏中打开 **Superagent** 来监督智能体。面板优先显示需要人处理的工作，然后是系统健康状况和历史。本文建立在 [000 理念](000-philosophy.md) 到 [004 提示词](004-prompts.md) 的基础上。

## 三个问题

打开面板会按以下顺序回答三个问题：

1. 现在有需要我处理的事吗？
2. 系统是否健康，是否在做正确的事？
3. 一项工作的历史是怎样的，从触发、评估到工单？

## 标签页

标签页遵循工作流：**概览**、**来源**、**触发**、**评估**、**执行** 和 **设置**。在仓库和账号的安装配置成功之前，概览会显示缺少什么，并链接到相关设置。

| 标签页 | 显示的内容 |
| --- | --- |
| 概览 | 需要处理的工单、系统问题、过去 24 小时的活动计数，以及执行器负载。每个区块都链接到其详情页 |
| 来源 | 来源状态、安装配置问题和非零计数。被过滤的触发和被放弃发送的消息与概览使用相同的 24 小时窗口 |
| 触发 | 按已被订阅、评估中、24 小时内有新触发或全部线程筛选的线程。每个线程按最新在前显示其触发、决定和订阅 |
| 评估 | 决定及其理由和匹配的规则 |
| 执行 | 执行器状态、暂停处理，以及按进行中、待处理、执行中、等待新触发或已结束筛选的工单。工单详情显示操作、授权、等待中的输入、订阅和派工 |
| 设置 | 来源、评估、执行、提示词和部署。每个分组都包含其保存历史 |

### 阅读单条记录

被放弃发送的消息会链接到它的工单；没有工单时链接到它的线程。来源页面会说明是它的对话消失了，还是来源不再监听它。

仍由某个执行器负责的人工跟进会标记为 **已送达工单**，且不经过评估。线程还会显示交回原因和仅作上下文的订阅。**重新评估** 可以把该跟进送入评估，或重试一个没有有效研判的触发：被其来源过滤的、评估未完成的，或已送达但既没有非停止决定也没有执行器确认的消息。

工单详情显示最初的触发、决定及理由、范围和策略版本。派工和次要详情折叠在即时操作下方。**重试** 可用于输入送达失败，或在报告受阻或失败后等待人处理的工单。已结束的工单会显示结果，例如 **PR 已合并** 或 **人工停止**。

## 设置分组

- **来源：** 每个来源一张卡片，包含其开关、字段和已验证的账号信息。GitHub 提供接收全部消息的开关，用于新 Issue、pull request、评论和默认分支 CI；GitLab 提供同样的开关，用于 Issue、合并请求、note 和 CI。只启用一个 Git 来源。轮询上限在「高级」下。
- **评估：** 策略版本和规则，接着是 **在各来源上** 和评估设置。每个来源标签页包含其允许名单、准入表和机器人名单。准入表区分接收范围、发送者是否在名单内，以及消息是否点名智能体。评估设置选择接单模式、时限和研判模型。
- **执行：** 执行器模型、并发数、目录根路径、准备命令和禁止调用的命令。点击一个可用的变量会把它插入准备命令。
- **提示词：** **编辑** 可修改团队段落、内置段落和技能。**完整提示词** 显示组装后的文本，并与已保存的文本或默认内容比较。**历史** 列出各个版本。编辑过的内置段落会标记为已改，并且可以恢复默认内容；模板会列出其必需的占位符。

  升级若改变了某个被覆盖的默认内容，会将其标记为 **默认内容已更新**。面板在团队文本上方比较旧默认内容和新默认内容。如果没有记录旧默认内容，则改为比较团队文本与新默认内容。选择 **保留我的文本** 或 **改用新的默认内容**。已移除段落的覆盖会列在标签栏下方，并在下次保存时丢弃。
- **部署：** 启动问题及 **重新检查**、状态目录和本机上限。保存的上限无需重启即可生效。DeepSeek Harness 插件管理器提供同一个页面。

## 搜索

页头搜索按文本、id、飞书消息 id 或已存储的链接（例如 GitHub 评论 URL 或 GitLab note URL）查找触发。飞书消息链接只有在飞书随原消息一起送达时才可以搜索。

搜索还可以按 `#12`、`!12`、GitHub URL 或 GitLab URL 之类的引用查找线程，并按标题或匹配的线程查找工单。

## 原则

1. **聚焦重要的事。** 每个元素都回答三个问题之一，否则就删掉。一个数字只有在会改变监督者行为时才会出现。
2. **精确定义。** 类别有可检查的定义，互斥且覆盖所有情况，就像工单阶段那样。标签说明一行在等谁、需要什么，而不是内部状态码。
3. **每个概念只有一个位置。** 来源状态属于来源；线程和触发属于触发；决定属于评估；工单属于执行。设置按它们所配置的概念分组。概览汇总这些页面并链接到它们，而不是变成另一个详情视图。
4. **领域结构。** 面板使用领域术语。内部标识只出现在折叠的详情中，在可以解析时用名称代替标识。
5. **如实的状态。** 计数等于它所链接列表的长度，任何状态都不与其他事实矛盾。
6. **默认安静。** 健康状态不占额外空间。问题必须可操作；一次性的网络错误还不够。需要人处理的行直接提供其操作。页面说明保持一句话，把更多细节放在 (?) 提示中。破坏性操作需要确认。
7. **一致的控件。** 使用 DeepSeek Harness 的设计 token 和控件行为。相同的信息在面板各处应看起来相同。每个设置块有一个保存栏，仅在存在改动、保存正在运行或保存失败时可见。
