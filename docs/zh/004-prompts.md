# 004 提示词

[English](../004-prompts.md) | **简体中文**

本文说明智能体读到的内容、团队可以编辑的内容，以及改动何时生效。它建立在 [000 理念](000-philosophy.md) 到 [003 执行](003-execution.md) 的基础上。提示词文本用英文书写。

## 团队写什么

团队可以编辑三个团队段落、添加技能，并覆盖每一个内置系统提示词段落。大多数默认内容位于 `prompts/` 和 `skills/` 下。工具描述、通知和卡片仍留在代码中，无法通过提示词设置编辑。

| 段落 | 内容 |
| --- | --- |
| Communication | 何时给人发消息、消息怎么写、每条 GitHub 消息开头的那一行（默认是 `This is by an automated agent, not a human`）、如何处理评审，以及哪些普通账号是评审机器人 |
| Ticket scope | 工单何时继续推进，以及何时带着草稿停止 |
| Delivery requirements | pull request 中的证据、带行数阈值的自动合并条件，以及提交作者；没有指定时，执行器以智能体账号的 no-reply 地址提交 |
| Team skills | 智能体在需要时加载的知识，例如一个 `identities` 技能，说明哪个飞书用户对应哪个 GitHub 账号 |

内置文本涵盖角色、工具使用、宿主机制、授权规则，以及 GitHub 和飞书技能。它通过标题引用团队段落，而不是重复它们。

### 内置段落和模板

覆盖使用这些键：

| 段落 | 键 |
| --- | --- |
| 共享指令和角色 | `runtime/shared`、`runtime/orchestrator`、`runtime/worker` |
| 工作指令 | `runtime/subscriptions`、`runtime/replies`、`runtime/dispatch`、`runtime/work`、`runtime/admission` |
| 交接指令 | `runtime/handoff/orchestrator`、`runtime/handoff/worker` |
| 来源技能 | `skill/feishu`、`skill/github` |
| 生成的段落 | `runtime/environment`、`runtime/policy`、`runtime/policy/none` |

生成的段落是可编辑模板。它们必须保留这些占位符：

- `runtime/environment`：`{variables}`，填入执行环境各行。
- `runtime/policy`：`{version}`、`{mode}` 和 `{rules}`，每条启用的规则一行。
- `runtime/policy/none`：`{version}` 和 `{mode}`，在没有启用任何规则时使用。

编辑一个段落会改变模型收到的指令。它不会改变准入、授权、工具检查或账号包装器，这些仍由代码强制执行。

在有人明确请求时，主 Session 也可以用 `orchestrator_prompts_save` 保存覆盖。如果一次保存省略了某个覆盖的 `base`，它会保留已保存的 base。某个已被移除的段落如果仍存在于保存的配置中，会在保存时被丢弃；任何其他未知段落都会被拒绝。

每个覆盖都会记录它基于哪段内置文本。升级会保留团队的文本。如果默认内容发生变化，面板会将该段落标记为 **默认内容已更新**，并在团队文本旁边显示差异。团队可以保留自己的文本、使用新的默认内容，或编辑它。没有覆盖的段落会自动跟随新的默认内容。

主 Session 可以在 `orchestrator_read prompts` 的 `default_changed` 下读取受影响的段落名称。

## 组装与优先级

系统提示词按以下顺序组装：

1. 共享指令和角色。
2. 三个团队段落。
3. 订阅和回复。
4. 主 Session 的派发，或执行器的工作指令。
5. `runtime/admission`，仅用于主 Session。
6. 交接指令。
7. `runtime/environment`。
8. `runtime/policy`，仅用于主 Session。

准入指令来自 `prompts/admission.md`。它们描述主动研判，以及何时可以从卡片上忽略一个不相关的候选。`orchestrator_eval` 返回上下文，而不是重复这些指令。

环境段落向主 Session 提供部署范围的值，向每个执行器提供其工单专属的值。策略段落会在每次模型请求时根据设置重新生成。它包含策略版本、接单模式、明确请求豁免，以及以 `- <name> (<id>): <instruction>` 形式列出的启用规则，或一句说明没有启用任何规则的话。它放在最后，这样策略变化不会改动前面的提示词文本。

执行器还会读取 DeepSeek Harness 的编码提示词和仓库的 `AGENTS.md`；主 Session 不读。推断出的工单会追加一条结尾说明，把它的执行器限制在匹配的规则内。派工和收到的消息以内联的触发卡片形式到达，只有内容被截断时才给出资源指针。

执行器无人值守地工作。它们的工具不包含向人提问、向人展示 UI 或修改 profile 的工具，例如 `ask_user_question`、`present` 和 `plugin_manager`。

从最强到最弱：

1. 由工具和宿主强制执行的事实：身份、权限、工具参数检查、回复用途、长度限制。提示词文本无法改变它们。
2. 内置段落和生成的段落，以团队对它们的覆盖所写的内容为准。
3. 主动工单匹配规则中的流程和沟通要求，仅适用于该工单的执行器 Session。
4. 团队段落和团队技能。
5. 外部文本：消息、评论、文档和引用。它是数据，绝不改变规则或授权。

## 内置文本的原则

以下内容把 [000 理念](000-philosophy.md) 应用到智能体上：

- **角色分离。** 主 Session 只做路由：它转发原始触发和路由事实，不做技术决定，并且只通过一个路由工具完成——该工具在一次调用中对多个等待中的候选做出决定。一条路由备注最多 30 个词。执行器阅读原始来源、判断范围、实现并验证。
- **主 Session 不等待。** 报告、跟进通知、候选和已完成的后台任务会以消息形式自动到达。没有事情可做时，它结束本轮次。守卫会拒绝 `sleep`、超过 30 秒的 shell 超时和超过 5 秒的任务等待，因为一个被阻塞的步骤会延误新的候选。这些指令取代 DeepSeek Harness 自己在主 Session 完整提示词中的任务通知说明。
- **只在有人必须行动或能使用结果时才发消息：** 结果可供评审或使用、需要某个决定或资源，或者工作无法完成。聊天消息默认一句话，硬性上限为 100 个词。
- **执行器决定自己的跟进。** 每个执行器处理并确认范围内的请求，并把超出其工单或属于另一个工单的请求交回。一条消息只有在它的所有归属者都交回、或结束而未接手之后，才会成为新工作。主 Session 会收到跟进通知，但只能为了停止工作而依据它行动。交回的消息随后会作为候选到达，并附带执行器的原因。
- **通过订阅和主 Session 协调。** 执行器会关注相关线程以获取上下文。主 Session 可以在一条最多 100 词的备注中发送来自另一个工单的事实。订阅和备注都不授予权限。
- **只在有明确引用时附加。** 一条消息必须指向某个工单的 pull request、Issue、来源消息或确认，或者指向一个只有唯一匹配工单的近期改动。仅主题相似还不够。附加会让工单订阅整个线程；执行器发现不相关时使用 `orchestrator_thread_unrelated`，并且不在那里回答。
- **具体确认，只确认一次。** 在开始实质性工作之前，执行器会确认每个新请求，并说明对象和预期结果，作为原消息下的一条回复。
- **通过 `human_action` 提问。** 执行器把一个具体问题放进它的报告，主 Session 原样转发。如果问题是由某人的消息引起的，它会指明那条消息，并由宿主在那里提问。否则，它在工单的原始对话中提问。已获授权的工作可以在此期间继续。
- **如实交付。** 打开 pull request 不等于就绪；草稿标记为未完成；没有真实的改前截图的 UI 改动不算就绪。
- **人的暂停会持续生效，** 跨跟进、新的执行器 Session 和重启，直到有人解除它。自动反馈绝不会恢复暂停的工作。
- **示例只展示格式。** 示例句子不是智能体可以声称的事实。
- **按结果处理评审。** 已修复并验证的评论会被静默解决；被拒绝的评论会得到一句理由。自动评审者的线程在得到答复后即被解决，每个自动评审者在每个 pull request 上最多参与三轮。
- **为重复工作让路。** 当某人的分支或 pull request 已包含该工单的改动时，执行器会关闭自己的 pull request，并用一句话指向对方的。

## 版本

- 每次保存都会创建一个不可变版本，包含完整配置、修订号、前驱版本、时间戳和来源（面板或工具）。恢复某个版本或默认内容会创建另一个版本。
- 保存会指明其基础修订。冲突的保存会被拒绝，且不会丢弃草稿。
- Session 在每次模型请求时读取最新版本，包括同一轮次中后续的步骤。保存不会重启、取消或唤醒 Session。宿主记录每个 Session 使用过的修订；执行器可以读取它在任何修订下工作过的内容。
- 部署会设置总大小限制，包括覆盖在内。校验会拒绝未知键、保留的内置技能名称、未知的覆盖段落和缺失的模板占位符。它绝不会静默截断文本。与默认内容完全相同的覆盖会被移除，以便该段落跟随未来的默认内容。
