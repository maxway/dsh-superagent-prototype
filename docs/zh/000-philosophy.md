# 000 理念

[English](../000-philosophy.md) | **简体中文**

dsh-superagent 是一个框架，也是一种与智能体协作的方式。它的核心原则：

**占用尽可能少的人工注意力，提供尽可能多的价值。**

项目的每一部分都以它消耗的注意力来衡量。一条消息、一个通知、一个问题、一个设置、一个面板元素和一段文档，都会消耗某人的注意力，因此每一部分都必须带来超过这份消耗的价值，否则就删掉。

## 对智能体的要求

- **只在被请求时、或书面规则允许时行动。** 一个请求只有直接面向智能体，并且来自团队允许的人，才算数：允许名单上的人，或团队开放接收请求的对话中的任何人。没有人请求的工作需要团队写下的规则，并且以一种只记录智能体本来会做什么的模式开始。
- **只在有人必须行动、或能使用结果时说话。** 它确认请求一次，并说明会做什么。工作时保持安静。结果就绪、需要决定或无法完成时，再写消息。消息简短，并发到提出请求的对话。
- **一次只问一个具体问题，** 以结构化形式提出，让问题真正到达人那里，而不是留在一份长报告里。
- **以影响而非投入来决定何时停止。** 局部改动的终点是可审查的结果。需要设计决定的改动，带着一个明确的问题停下。
- **如实报告。** 草稿标明未完成，失败报告为失败，绝不为了回避提问而绕过限制。

## 对设计的要求

- **概念少。** 设计只有它的领域概念，例如来源，以及它们的具体实现，例如 GitHub 和飞书。一个业务需求会成为其中某个概念的属性，或智能体遵循的一段提示词。设计不会为它新增概念。
- **设置少。** 当一种取值适合几乎所有团队时，用默认值代替设置。团队用文字描述的行为属于提示词文本，不是设置。
- **面板只显示需要人处理的事。** 它首先列出等待人处理的内容。健康状态不占空间。
- **文档按顺序阅读。** 每篇编号文档只建立在此前的文档之上，读者永远不需要尚未介绍的概念。

## 责任

智能体以你们团队每天都能看到的账号发表评论、提交 pull request 和给人发消息。它发出的每条消息都消耗同事的注意力，而你要为此负责。智能体能力越强，运营者对团队的责任就越大：

- **从窄开始。** 先用一份简短的允许名单，主动工作只做记录。等看到智能体本来会做什么并且觉得正确后，再放宽两者。
- **为更少噪音而调整。** 当智能体太吵时，把它的提示词改得更短更严格，或者暂停它。不要用更多消息来解释噪音。
- **不要用它制造数量。** 大量 pull request、群发消息和忙碌工作，给团队带来的成本高于价值。
- **为它所说的话负责。** 阅读智能体以你的名义发布的内容，发现错误时在提示词中纠正。

目标是：在对的时间给出对的帮助，其他时间什么都不做。
