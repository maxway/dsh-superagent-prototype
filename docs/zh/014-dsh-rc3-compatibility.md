# 014 DSH 0.2.2 rc.3 兼容候选

这是开发候选，不代表已部署到生产，也不声称完全兼容。项目的开发依赖固定为 rc.3，现有 peer 和 engine 版本范围仍允许该范围内的 rc.1 及之后的预发布版本。版本范围不保证运行时安全。

[rc.3 发行说明](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.3)介绍了可选的聊天导入插件和 Windows Desktop 更新器修复。已安装的升级索引没有 rc.2 到 rc.3 的指南；这一缺失不能证明本项目使用的接口没有变化。此前的 [rc.2 调查](013-dsh-rc2-subagent-lifecycle.md)说明了与本候选相关的所有权和准入变化。

候选的 worker 预设不再提供原生子智能体工具。项目 guard 会拒绝已识别的受管理 worker 及其子智能体使用已知原生子智能体工具，包括保留旧预设的 worker。它沿可用的在线和持久化祖先链向上查找，最多 128 层、两秒；缺失、不可读取、循环、超时或更深的祖先链仍无法识别。它不能撤销已准备的调用，也不能覆盖其他入口或外部、GUI 工作。这不是完整隔离。

独立锁定依赖的 [rc.3 子智能体契约](../../contracts/subagent/rc3/contract.test.mjs)使用内存替身测试真实的 rc.3 子智能体运行时。rc.2/rc.3 停止路径尽力 interrupt 已登记的 child 并等待树工作，而不是释放本地 activation。由调用者投递的外部执行不会被中断，外部释放失败可能被遗漏，本地 child 及其未认领 inbox 也可能仍处于停泊状态。目录只要含 child 或 diagnostic（包括历史记录），或观察到树工作，即使没有其他错误，候选也报告清理未确认。目录为空或等待返回 false，不能证明没有遗留活动。既有持久化 Ticket 隔离会阻断后续自动工作，且不会自动解除；须核查原进程与残余工作。意图记录前崩溃、GUI 直接操作、目录遗漏及未确认的外部工作仍不受该保护。rc.1 路径则释放目录中存活的 child。`drainDescendants` 不是可以直接替换的方法：它会关闭可复用根节点的准入，直到根节点离开注册表。同进程关闭失败时，候选保留数据库和状态锁；这不代表已部署到生产。

在 Windows 和 Node.js 24.21.0 上，候选通过类型检查、构建、1,451 项默认测试（34 项跳过）及 13 项独立锁定的 rc.1/rc.2/rc.3 子智能体契约。此前验证在 rc.1 和 rc.3 上均复现了四项 worker 关闭测试失败：测试直接调用报告工具，却没有结束模拟 worker 的回合。测试夹具现会显式结束该回合并等待停止标记。这修复的是测试设置，并不证明真实进程已被清理。

这些契约不测试真实外部进程、完整 DSH profile、模型、跨进程恢复或生产部署。验证修改时须使用独立配置的非生产 profile、DSH home、状态、端口、凭据及测试仓库，并禁用飞书；仅有 worktree 不能隔离这些资源。不要仅凭此候选升级或重启生产。
